# Research — Product Naming Criteria and Candidates

**Date:** 2026-09-14
**Phase:** discovery
**Status:** preliminary research, not a decision

## Context

`config/project.env` currently has `PROJECT_NAME=` and `PROJECT_SLUG=` empty per ADR-0001 follow-ups: "Finish product naming; PROJECT_NAME and PROJECT_SLUG stay blank until that decision is made." `docs/PRODUCT.md` states final product name intentionally undecided, product promise is phone-first universal TV remote, joint priorities reliability and premium visual quality.

## Naming constraints from PRODUCT.md and DOMAIN.md

- **Phone-first universal TV remote**, not TV brand specific.
- **Universal** means one app honestly supporting many ecosystems behind consistent experience, not claim every TV works.
- **Local-first**, no account, no cloud required for core use.
- **Premium visual quality** — name should feel premium, not cheap utility.
- **Accessible, familiar, one-handed use** — name should be simple, memorable, ordinary language.
- **No behavioral analytics** — privacy-safe, so name should not imply tracking.
- **Android first, iPhone path preserved** — name must work cross-platform, not Android-specific.
- **Avoid vendor trademarks:** Cannot use "Samsung", "LG", "Android TV", "Roku", "Google TV" in name per trademark guidance [3](https://forum.webostv.developer.lge.com/t/do-i-need-lg-permission-to-publish-a-remote-control-app-for-lg-tvs-on-galaxy-store/28119) — compatibility naming allowed only as "for X", not as product name.
- **Avoid implying official partnership:** Must not imply LG/Samsung/Google endorsement.
- **Short, install/open → find → pair → control in under 2 min** — name should be quick to type, voice-searchable.

## Additional engineering constraints

- `PROJECT_SLUG` used in generated text; should be short kebab-case, no spaces.
- Domain and package name availability not verifiable in sandbox (egress allowlist blocks most domain registrars). Must mark as preliminary and require human check.
- Play Store search: many "Remote for LG/Samsung" apps exist [2](https://play.google.com/store/apps/details?id=dev.niamor.webosremote&hl=en_US) [3](https://play.google.com/store/apps/details?id=com.meisterapps.lg&hl=en_US) — need differentiation from single-vendor remotes.
- Must work as verb/noun: "Open ___", "Use ___ to control TV".

## Criteria for evaluation

| Criterion | Why | Test |
| :--- | :--- | :--- |
| Distinctive vs single-vendor remotes | Market crowded with "Remote for LG TV" etc | Play Store search "TV remote" shows many single-brand apps; name must not be "LG Remote" |
| Premium, not gimmicky | PRODUCT.md says premium visual quality | Avoid "Super", "Mega", "Ultimate" |
| Short, memorable, pronounceable | First-run journey <2 min, ordinary language | <=2 syllables ideal, <=3 acceptable |
| No vendor trademark | Legal | Does not contain Samsung, LG, Roku, etc |
| Suggests universal/hybrid but not overclaim | Honest compatibility promise | Words like "Universal", "Every", "All" risk overclaim; prefer "Living room", "Lounge", "Hub", "Beam" |
| Works for future non-TV devices | PRODUCT.md says leave room for soundbars etc later | Avoid "TV-only" words if possible, but V1 is TV-first |
| Available as slug | Engineering | Lowercase, no spaces, suitable for package id |

## Candidate shortlist (preliminary, no trademark clearance)

All candidates are **proposals only**, not decisions. Each needs human trademark/domain/Play Store availability check before acceptance.

### Tier 1: Simple, premium, phone-first

- **Lumen** — light, living room, premium feel; slug `lumen`; risk: existing lighting brand, but short and premium.
- **Sora** — sky, open, short; slug `sora`; risk: AI model named Sora (OpenAI) may cause collision.
- **Hearth** — living room heart, warm, premium; slug `hearth`; evokes household, not techy.
- **Beacon** — find device, guide; slug `beacon`; suggests discovery, matches DOMAIN.md Discovery entity.

### Tier 2: Descriptive, universal hint

- **Cove** — living room cove, cozy, short; slug `cove`; suggests household.
- **Relay** — phone relays command to TV, hybrid control hint; slug `relay`; verb-friendly "Relay to TV".
- **Dial** — old TV dial + modern, simple; slug `dial`; but may imply phone dialer.
- **Avenue** — broad, but maybe too generic.

### Tier 3: Functional, explicit remote

- **Taproom** — tap to control living room; slug `taproom`; but "room" may imply bar.
- **Remote &** — "Remote &" with suffix? Not good.
- **Living Remote** — clear, but longer; slug `living-remote`; describes promise.

**Not recommended:**
- Anything with "Universal" — overclaims per DOMAIN.md definition.
- "Smart Remote" — crowded, generic, many existing apps [4](https://play.google.com/store/apps/details?id=com.sensustech.lgremote&hl=en_US)
- "ThinQ", "SmartThings", "Bravia" — vendor trademarks.
- "IR Blaster" — limits to IR, V1 is hybrid.

## Recommendation for process

1. Product owner selects 3 finalists from Tier 1, checks Play Store, USPTO TESS (outside sandbox), domain .com/.app availability, and Google search collision.
2. Run informal user test: "If you lost your TV remote, would you search for X?" — does name surface intent?
3. Record final decision in ADR with trademark search notes (not legal opinion).
4. Then set `PROJECT_NAME` and `PROJECT_SLUG` in `config/project.env` via reviewed PR, per `scripts/init-project.sh` guidance.

Until then, keep `PROJECT_NAME` blank to satisfy ADR-0001 follow-up and avoid premature commitment.

## Relation to V1 ecosystems

Name should not tie to Samsung or Android TV, since V1 is Android TV + Samsung Tizen but roadmap adds LG webOS and others. Universal name supports honest Tested/Expected/Unsupported compatibility list without rebranding.

## Open questions

- Should name hint at local-first/privacy? e.g., "Local" suggests privacy but may sound technical.
- Should name be noun or verb? "Beacon" is noun, "Relay" is verb — both work.
- Business model: V1 free, no ads, no subscription — name should not imply freemium.

No decision made here; this is research evidence for future naming ADR.
